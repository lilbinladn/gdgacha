# Demon Gacha

A Geometry Dash demon card collector. Open packs of five cards, collect every rated demon in the
game, and chase the AREDL-rated Mythic and Celestial pulls.

Built as a static site, so it deploys to GitHub Pages with no backend.

## What's in it

- **Packs** — one pack every **3 minutes**, up to **10 stored**. The timer runs on the clock, so
  packs accumulate while the tab is closed. Each pack has **5 cards**, and the fifth card is
  always **Rare or better**.
- **Cards** — every card is a real Geometry Dash level with its **difficulty** (Easy → Extreme
  Demon), its **AREDL rating** (leaderboard position, when the level is listed), its GDDL tier
  rating, creator and enjoyment score.
- **Rarities** — Common, Uncommon, Rare, Epic, Legendary, Mythic and Celestial. Rarity is derived
  from the level itself: difficulty sets the base, the hardest few percent of each difficulty get
  bumped, AREDL top 300 becomes Mythic and AREDL top 50 becomes Celestial.
- **Foil cards** — 8% of pulls are foil variants with a shimmer treatment.
- **Discord login** — OAuth2 authorization-code flow with PKCE, entirely in the browser (no
  client secret, no server).
- **Collection & Index** — filter your collection, or browse all 11,000+ demons with search,
  difficulty, rarity and "owned only" filters. The index is ordered by AREDL difficulty, hardest
  first.
- **Owner powers** — the site owner's Discord account can add packs at any time, ignoring the timer
  and the storage cap (see [Owner powers](#owner-powers)).

## Data sources

`src/data/levels.json` is generated by `scripts/fetch-levels.mjs` from two public community APIs:

| Source | What it provides |
| --- | --- |
| [GDDL](https://gdladder.com) (`gdladder.com/api/levels`) | Every rated demon in the game, its difficulty and tier rating |
| [AREDL](https://aredl.net) (`api.aredl.net/v2/api/aredl/levels`) | All Rated Extreme Demons List positions and points |

Card thumbnails are the still of each level's GDDL showcase video
(`img.youtube.com/vi/<id>/mqdefault.jpg`), falling back to the community thumbnail database at
`levelthumbs.prevter.me` and then to a demon icon. Nothing is downloaded — the images are hotlinked,
so the dataset stays small.

Refresh the dataset whenever you want newer list data:

```bash
npm run fetch:levels
```

The fetcher is throttled and caches pages in `scripts/.cache`, so an interrupted run resumes where
it stopped. Delete that folder to force a clean refetch.

## Run locally

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # typecheck + production build into dist/
```

## Discord login setup

The login button needs a Discord application (about two minutes):

1. Open the [Discord Developer Portal](https://discord.com/developers/applications) → **New
   Application**.
2. Under **OAuth2**, copy the **Client ID**.
3. Under **OAuth2 → Redirects**, add every URL the site is served from, exactly:
   - `http://localhost:3000/` for local development
   - `https://<your-user>.github.io/<your-repo>/` for GitHub Pages
4. Build (or start the dev server) with the client ID:

   ```bash
   VITE_DISCORD_CLIENT_ID=123456789012345678 npm run dev
   ```

   Create a `.env` file with `VITE_DISCORD_CLIENT_ID=...` to keep it out of your shell history.

No client secret is used or needed — the browser exchanges the code with PKCE, which Discord
supports for public clients. Without a client ID the site still works: it falls back to a guest
profile and shows the setup steps in the sign-in dialog.

## Owner powers

The owner's Discord account can add packs to itself whenever it likes, with no timer and no
storage cap. Match it by Discord username or numeric user id, comma separated for several people:

```bash
VITE_OWNER_DISCORD=your_discord_username npm run dev
```

On GitHub Pages, set it as a repository variable named `OWNER_DISCORD` (Settings → Secrets and
variables → Actions → Variables). The built-in default is `lilbinladn`.

This is a convenience, not a security boundary: saves live in `localStorage`, so anyone can edit
their own numbers regardless of what the client allows.

## Deploy to GitHub Pages

1. Push the repo to GitHub.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Optionally add the client ID as a repository variable: **Settings → Secrets and variables →
   Actions → Variables → New variable**, name `DISCORD_CLIENT_ID`.
4. Push to `main`. `.github/workflows/deploy.yml` typechecks, builds and publishes `dist/`.

The build uses a relative base, so it works from `https://<user>.github.io/<repo>/` as well as from
a custom domain. Routing is hash-based (`#/collection`), so no 404 rewrites are required.

## Save data

Progress is stored in `localStorage`, keyed per Discord account (or per guest device). A static
site has nowhere to keep server-side state without adding a backend, so a collection does not sync
between devices or browsers. If you want that later, the natural next step is a small
Cloudflare Worker plus a database, with the same client calling it instead of `localStorage`.
